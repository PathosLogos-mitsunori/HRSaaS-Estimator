# 削減効果試算アプリ

HR SaaS の導入による年間工数の理論上の削減時間、FTE 換算、金額換算を試算する Web アプリです。無料／有料版の選択、会社情報、各領域で１製品の選択、選択領域の質問、結果と算定根拠、Excel 出力、相談申込を含みます。

## ローカル起動

Node.js 22.13 以上で `npm ci`、`npm run dev` を実行し、表示されたローカル URL へアクセスしてください。ビルド確認は `npm run build` です。計算部分だけなら `public/calculator.html` をブラウザーで開けます。相談申込は Web サーバー上の `/api/consultations` とデータベースの設定が必要です。

`public/` の JavaScript と CSS が試算本体です。`public/labor-data.js` に労務領域の工程、参照値、試算係数、`public/product-question-data.js` に共創PF・Combosite の質問を置き、`public/app.js` で入力と結果を処理しています。`app/api/consultations/route.ts` は希望者の相談申込を保存します。通常の試算だけでは送信しません。`/admin` はサイト所有者認証とデータベースの設定が必要です。

## 算定の前提

- 入力するのは現行の作業時間、年間件数・回数、現在の処理方法です。導入後の時間は入力しません。
- SmartHR の各工程：削減率 = 工程別基礎率 × 現行方法係数 × SmartHR 対応範囲係数。外部システムへの受渡しを無根拠に削減せず、共創PF・Combosite と重なる工程を除きます。係数はこのアプリの仮定で、SmartHR 公表の業務別保証値ではありません。
- OfficeStation：提供された定量効果試算シートの工程別「導入後分数／現在分数」を、入力された現在分数に掛けます。住民税通知書の配付は年間全体の工数として扱います。
- 共創PF：定例の人的連携作業は導入後０分、例外・対象外データの補正は現行と同時間と仮定し、手入力件数・ファイル連携回数・例外件数それぞれに連携先数を掛けます。共創PFが選ばれ、他の対象領域が２つ以上ある場合のみ質問します。
- Combosite：別途提示された質問別の削減率レンジの中点を試算値に使います。質問画面には率を出さず、結果の「算定ロジック」に示します。
- その他の領域：現行作業状態、連携方法、得意領域の独自係数による概算です。
- 年間削減 FTE = 年間削減時間 ÷（所定労働日数 × １日当たり所定労働時間）。年間削減金額 = 年間削減時間 × 時間単価。これは SaaS 費用を控除した純利益ではありません。

結果は対象業務が SaaS 標準業務に変更できた場合の理論値です。実際の効果や製品仕様を保証しません。各企業の運用・契約・連携・例外処理を確認してください。

## GitHub へ配置する場合

このアーカイブの中身をリポジトリのルートへ配置してください。`.env` や認証情報をコミットしないでください。静的な計算画面のみを公開する場合、`public/` の中身を静的ホストの公開ディレクトリに置けます。相談申込と管理画面を使う場合は、Next/vinext 対応環境とデータベースの設定が必要です。

### SmartHRの社会保険手続き

SmartHR内で完結する対象業務を前提とし、外部システムへの受渡しは削減対象外です。入社・退職・契約更新・身上変更から社保届出工程を除外し、「健康保険の届出」と「その他の社会保険・雇用保険の届出」に分けて一度だけ計上します。健康保険の届出を選んだときだけ健保組合を5択で確認し、その条件を適用します。協会けんぽ・関東ITS・TJKは工程基礎率をそのまま使用します。その他健保では帳票自動作成の削減を見込まず、マイナポータル申請不可なら提出・完了確認の削減も見込みません。基礎削減率はアプリ独自の試算仮定であり、個々の帳票・プランでのSmartHR対応を保証しません。

公式資料：[健康保険タイプ](https://support.smarthr.jp/ja/help/articles/360026265453/)／[届出書類ごとの電子申請の送信先](https://support.smarthr.jp/ja/help/articles/e8b52989-60ad-4e67-b971-4682c7353d74/)

### SmartHRの給与明細

現行の給与計算結果データ取込は1回の所要時間と年間取込回数、紙明細の印刷・封入・手渡し・郵送は1枚の所要時間と年間の紙明細枚数を別々に入力します。共創PFを選択していれば給与データ取込の人的作業時間は0分とし、未選択ならSmartHRでも現行の取込操作が残ると仮定します。共創PF側の給与情報連携で同じ作業が計上されているときは、SmartHRの取込質問を除外します。印刷・配付は全件を電子配付できた場合の理論値で、同意や紙対応が残る場合は過大になります。共創PFの給与情報連携を選んだ場合は、SmartHR側のデータ取込は二重計上を避けて除外します。公式：[給与明細機能とは](https://support.smarthr.jp/ja/help/articles/360026107314/)／[給与・賞与明細情報を取り込む](https://support.smarthr.jp/ja/help/articles/360059997153/)

### SmartHRの源泉徴収票・住民税決定通知書

質問は現行業務を尋ねます。源泉徴収票はデータ取込回数、紙の印刷枚数と配布通数を分けます。住民税決定通知書は紙での受領回数、封入通数、配布通数を分けます。導入後は源泉徴収票データ取込と紙通知書の受領・仕分けに現行時間が残ると仮定します。紙書類の作成・配布をなくす効果は全件電子配付できる理論値です。住民税通知にはeLTAXで電子データを受領する運用変更が必要で、紙の受領だけでは封入・配付の削減は実現しません。公式：[源泉徴収票機能](https://support.smarthr.jp/ja/help/articles/4409111670809/)／[特別徴収税額通知管理機能](https://support.smarthr.jp/ja/help/articles/466ed11b-4ba7-4a6b-b62e-d1b0301a36d8/)

### 入力根拠と勤怠管理

各領域の質問ページで入力した工数・件数の根拠（実測・集計済み／担当者による概算／仮置きの数値）を必須で確認し、結果の確認事項とExcelの回答・算定根拠に記録します。削減率には反映しません。勤怠管理は打刻・申請漏れの確認、承認・月次締めのみ試算します。勤怠データ集計と給与等への受渡しは重複防止のため除外しています。

### 算定方法の表示

「算定方法を見る」では、共通の計算式、選択した場合のみシステム間連携（共創PF）と給与計算（Combosite）、続いて労務領域・勤怠領域・タレントマネジメント領域・通勤費管理領域・退職金管理領域を、それぞれ独立した見出しで、選択された場合のみSaaS名付きで表示します。表示は選択状況に応じて更新され、入力画面には削減率や導入後時間を表示しません。
